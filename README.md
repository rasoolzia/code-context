# CodeContext

**CodeContext is a VS Code extension for exporting, importing, and sharing developer project context with AI.**

Turn files, folders, project structure, paths, and Git changes into AI-friendly context. Import generated context back into a workspace when you need to recreate files or project structure.

Exports open as editable untitled documents. Nothing is written to your workspace unless you explicitly save or create the files.

## Why CodeContext?

When working with AI coding assistants, you often need to provide more than a single file.

You may need:

- several related files
- a project's directory structure
- a list of relevant file paths
- the changes you are currently working on
- the complete before/after state of changed files
- or enough project context to recreate a structure somewhere else

CodeContext provides these workflows directly inside VS Code instead of making you manually copy files, build folder trees, or assemble Git context yourself.

## Features

### Export Content

Export one or more files, folders, or the complete workspace as Markdown containing file paths and contents.

Useful for sharing implementation context with AI assistants.

[Read the Export Content documentation](docs/features/export-content.md)

### Export Project Tree

Export a deterministic project directory tree without reading or including file contents.

Useful when an AI assistant needs to understand the structure of a project before working with its files.

[Read the Export Project Tree documentation](docs/features/export-tree.md)

### Export Paths

Export workspace-relative file paths as a structured text document.

```text
# Export Paths

src/app/page.tsx
src/components/Button.tsx
src/lib/utils.ts
```

Useful for quickly sharing a list of relevant files or feeding paths into another workflow.

[Read the Export Paths documentation](docs/features/export-paths.md)

### Import Content

Paste CodeContext Markdown generated by an AI or another CodeContext export and recreate or update files in the workspace.

Before modifying existing files, CodeContext validates the input and asks for overwrite confirmation.

[Read the Import Content documentation](docs/features/import-content.md)

### Import Project Tree

Create directories and empty files from a project tree without changing existing files.

Useful for recreating project structure before filling files with content.

[Read the Import Project Tree documentation](docs/features/import-project-tree.md)

### Import Paths

Create directories and empty files from a newline-separated path list.

Existing files are preserved.

[Read the Import Paths documentation](docs/features/import-paths.md)

### Generate Context from Paths

Paste a list of workspace-relative file paths and choose what kind of context to generate:

- **Content** — produces the same `# Code Context` Markdown as Export Content
- **Git Diff** — produces the same `# Git Diff` output as Git Diff, scoped to the provided paths

Useful when you already know which files are relevant and want to generate context without navigating the Explorer.

[Read the Generate Context from Paths documentation](docs/features/generate-context-from-paths.md)

### Git Diff

Export the current Git changes as a patch.

Git Diff includes:

- tracked changes
- staged and unstaged changes
- deleted files
- renamed files
- untracked files as additions
- Git metadata and standard diff context

From the Explorer context menu, Git Diff can be scoped to one or more selected files or folders. Without an Explorer selection, it operates across the workspace repositories.

[Read the Git Diff documentation](docs/features/git-diff.md)

### Before/After Git Context

Export the complete file contents before and after the current Git changes.

For changed files:

- **Before** is the complete file at `HEAD`
- **After** is the complete file in the current working tree
- untracked files have an empty before state
- deleted files have an empty after state
- renamed files preserve their old and new paths

Selections from the Explorer can scope the export to specific files or folders.

[Read the Before/After Git Context documentation](docs/features/before-after-git-context.md)

## Export and Import Workflow

CodeContext is designed around a simple two-way workflow:

```text
VS Code project
      │
      ├── Export Content
      ├── Export Tree
      ├── Export Paths
      └── Git Context
              │
              ▼
        AI / Human / File
              │
              ▼
      CodeContext Import
              │
              ├── Content
              ├── Project Tree
              └── Paths
              │
              ▼
        VS Code project
```

This makes CodeContext useful both for **giving project context to AI** and for **turning structured AI-generated context back into files**.

## Usage

All commands are available from the Command Palette under the **CodeContext** category.

Export commands open editable untitled documents:

- **CodeContext: Export Content**
- **CodeContext: Export Project Tree**
- **CodeContext: Export Paths**
- **CodeContext: Git Diff**
- **CodeContext: Before/After Git Context**

Git commands and export commands that support Explorer resources can also be used from the Explorer context menu.

Import commands open the shared CodeContext Import panel:

- **CodeContext: Import Content**
- **CodeContext: Import Project Tree**
- **CodeContext: Import Paths**
- **CodeContext: Generate Context from Paths**

### Typical AI workflow

1. Select the files or folder relevant to your task.
2. Export the project context you need.
3. Paste or provide the generated context to your AI assistant.
4. Let the AI analyze, modify, or generate the requested result.
5. Import generated CodeContext content back into VS Code when appropriate.
6. Review the changes before saving or committing them.

## Safety and Validation

CodeContext validates imported paths before creating or modifying files.

The extension protects against common unsafe filesystem operations, including:

- absolute paths
- path traversal such as `../`
- paths escaping the workspace
- conflicting file and directory paths
- unsupported or unsafe symbolic-link traversal

Existing files are not overwritten silently.

Large or binary content is handled conservatively where appropriate, especially for Git context exports.

## Requirements

- Visual Studio Code `1.138.0` or newer
- Git installed and available on `PATH` for Git Diff and Before/After Git Context

CodeContext has no runtime dependencies.

## Current Limitations

CodeContext currently focuses on project files, structure, paths, and Git context.

Routing reports for frameworks such as **Next.js** and **Nuxt** are planned for a future release.

Git operations require a Git installation and an accessible repository. Very large or binary files may have their contents omitted from context exports where reading the content is not appropriate.
