# Import Project Tree

## Purpose

Recreate directories and empty files from a project tree. This is the **Tree → Structure** workflow; it does not import file contents.

## Command and Workflow

Run **Import Project Tree** to open the shared CodeContext Import panel on the **Import Project Tree** tab. Paste a tree, select **Import Project Tree**, and choose a workspace folder if the workspace is multi-root. The parser validates the complete input before the shared structure writer creates anything.

The tree parser accepts the Unicode branches generated by Export Project Tree and common ASCII branches. A generated Project Tree Markdown document, including its title and text fence, can also be pasted.

## Filesystem Behavior

- Missing directories are created; existing directories are preserved.
- Missing files are created empty.
- Existing files are left completely unchanged.
- Empty directories in the input are retained.
- Duplicate equivalent entries are normalized and deduplicated.
- Ambiguous file/directory conflicts are rejected before writes.

## Security

Absolute paths, Windows drive paths, null bytes, `..` traversal, paths outside the selected workspace, and symbolic-link destinations are rejected. Parent components must be directories. Only the selected workspace folder is modified.

## Current Limitations

- Tree entries must be interpretable from indentation/branch levels; incomplete branches with missing parents are rejected.
- File contents are never imported, and existing file contents are never overwritten.
- If a filesystem failure occurs after some entries were created, those earlier creations are not rolled back.
